# blood-on-the-wall — CLAUDE.md

## What This Is

A counterfactual narrative history (textId: `'blood-on-the-wall'`): John F. Kennedy is assassinated in West Berlin on June 26, 1963, by a network tied to the Stasi, and the Cold War unfolds differently as a result. Four sections, `The Shot Heard in Berlin` → `Graduated Pressure` → `A Fog of Distrust` → `The Files Break Open`, tracing consequences out to 1993.

The guide is a historian who has lived entirely inside this history — never "alternate," "counterfactual," or "this timeline." `behavioralInstructions` in `config.js` forbid any acknowledgment that another version of 1963 exists, even under direct questioning. This is a stricter version of the guide-voice problem uncanny/plenitude also wrestle with (see `uncanny/CLAUDE.md`): here the model isn't just avoiding the explainer role, it's forbidden from ever stepping outside the frame at all.

## Status

Current section text (`source_texts/sections/*.md`) is hand-written prose, same as uncanny/plenitude. Follows the standard engine pattern — see the root `README.md` and `uncanny/CLAUDE.md` for the shared architecture (KV storage, entry consent flow, blank-Return continuation, evolve step, adding a new text). `public/index.html`, `style.css`, `app.js` are kept in lockstep with the other two texts' `public/` folders — only the historian-specific labels, section data, and consent-paragraph wording differ.

## Future work: generate from Monte Carlo Fiction timeline JSON

This history (and any future counterfactual-history texts) is conceptually generated by a separate repo, **Monte Carlo Fiction**, which produces structured JSON timeline files and renders them into prose. Right now that rendering happened by hand, once, outside this app — this app just stores the resulting markdown.

Idea for next time: skip the hand-written markdown step entirely. Drop the JSON timeline file into this app and have the model do the JSON → prose rendering directly, so the JSON stays the single source of truth (shared with Monte Carlo Fiction) instead of being hand-copied into markdown.

Two things to resolve before implementing (see root `README.md` "Future work" for the full note):
- **Render once, not per chat turn** — cache the rendered prose per section (reusing the pattern already in `api/evolve.js`) so `sections[idx]` stays a plain string and nothing downstream (word limits, the evolve length guard, `chat.js`) needs to change.
- **Section chunking** — the timeline JSON has no built-in notion of "4 reader-facing sections." Needs manual date-range groupings in `config.js`, or a boundary marker added to the Monte Carlo Fiction format itself. Confirmed this chunking step is needed regardless of rendering approach.
