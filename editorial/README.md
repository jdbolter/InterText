# Editorial workspace

The spine-and-fund packages for the text, their schema and build, the local author editor, and the tools that publish to or read from the shared KV database. The model is described in [`EDITORIAL-ARCHITECTURE.md`](../EDITORIAL-ARCHITECTURE.md); the design in [`CURRENT-DESIGN.md`](../CURRENT-DESIGN.md).

## Start

Requires Node.js 22 or later and a checkout. Without KV variables the workspace shows the bundled seed for inspection only. With `KV_REST_API_URL` and `KV_REST_API_TOKEN` in `.env.local` it shows the shared live version and can publish author revisions. No Vercel login is needed.

```bash
npm install
npm test
npm run editorial-preview
```

Open `http://127.0.0.1:4173` and stop the server with Control-C. Only one server can hold a port. If the workspace already opens there, refresh it, but restart the old process if the code has changed. To find it on macOS: `lsof -nP -iTCP:4173 -sTCP:LISTEN`; stop it from its own terminal if you can, otherwise `kill <PID>`. To run beside it: `EDITORIAL_PORT=4174 npm run editorial-preview`.

`editorial-preview` always builds first. To validate and regenerate the data without a server: `npm run editorial-build`.

## Review a synthetic reading without publishing it

```bash
npm run editorial-propose -- --session <run-folder> --section 1
```

This sends the current section package and the recorded contributing exchange through the proposal and review passes. It may read the current KV version but never initializes or writes KV. The proposal, review and reviewed draft are saved under the gitignored `editorial/proposals/`; refresh the preview and a matching proposal appears above the spine. **Review proposed changes** loads the reviewed subset as an unpublished author draft that can be revised; **Discard proposal** writes nothing; **Publish author revision** is the only action that creates a KV version, and it refuses if the section's head changed since the proposal. Proposal files are gitignored, so copy them to another checkout's `editorial/proposals/` to review them there.

## Source and generated data

- Edit files under `editorial/content/`.
- `editorial/data/` and `api/editorial-seed/` are generated by `npm run editorial-build`; commit the source and the regenerated data together.
- `synthetic-reader/output/` is gitignored. Copy any session needed as a lasting record into the section's tracked `provenance/` directory.

## Add a work

Create `editorial/content/<work-id>/work.json` conforming to `schema/work-manifest.schema.json`. IDs are lower-case hyphenated and stable. Work `order` sets the selector order; section `order` values and IDs are unique. Set a section's `package` to `null` until it has one. The tests compare each manifest with the text's `config.js`, so a renamed, added or reordered section must be changed in both.

## Package a section

1. Create `editorial/content/<work-id>/sections/<section-id>/`.
2. Add `spine.md`, with `<!-- intertext:passage <section-id>-p01 -->` before each passage.
3. Add `section.json`, following any existing section.
4. Put fund prose in short Markdown files under `fund/` and reference each from `section.json` with `markdownFile`. An empty `fundEntries` array is a valid faithful package.
5. Set the section's `package` in `work.json` to the relative path of `section.json`.
6. Run `npm run editorial-build && npm test`.

## Status meanings

- `candidate`: under evaluation; never offered to readers.
- `accepted`: offered to the text.
- `superseded`: replaced by another entry; kept as a record.
- `rejected`: a decision record; not offered.

`sourceStatus`: `not-required` (interpretive material), `needs-verification` (factual or quoted material without adequate support), `verified` (at least one descriptive HTTP(S) source).

## Author editing

**Edit section** edits spine prose and every field of each fund entry, and adds entries (kind, status, anchors, prose, cue, sources, source status, thread and order). Passage IDs, entry IDs and provenance are protected, and entries cannot be deleted: reject or supersede them. **Publish author revision** validates the whole package, checks that the loaded base is still the live head, writes a new immutable `author-revised` child with its update record, and advances the head atomically. It never rewrites the files under `editorial/content/`. The editor calls no model.

## Shared KV commands

```bash
npm run editorial-kv -- status --text digital-plenitude --section 1
npm run editorial-kv -- init   --text digital-plenitude --section 1
npm run editorial-kv -- export --text digital-plenitude --section 1
```

`init` is idempotent: it creates the baseline from the seed only when the section has no head. `export` writes the current snapshot under `editorial/exports/` (or the path given by `--out`); review that folder before committing it. `status` shows the live version.

## Deployment boundary

`.vercelignore` excludes this whole directory. Do not remove that line to make the editor reachable: authentication and a policy for the private manuscript and provenance data must come first. `editorial/research/` holds a working dataset of art-reception cases; the text does not load it.
